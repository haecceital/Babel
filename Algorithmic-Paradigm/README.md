# algorithm-paradigm

這資料夾中的內容是針對**演算法範式**的模板，而非是針對特定問題的解。至於具體處理資料或是解題的邏輯，我會將它抽象成函數，只保留這個算法的基本邏輯

## 用 Haskell 的原因

`data structure` 資料夾用 C++，是因為我認為該部分的重點是資料的處理方式，而其中又會碰到關於指標或是生命週期的問題，所以即使 Haskell 能更好地表達資料間的關係、邏輯(個人想法)，我最後還是選擇統一使用 C++ 來實作

## 用 Haskell 實作的優點

這部份是我的主觀想法，在我實作的過程中都深有體會

1. **型別簽名讓我能更熟悉該算法的核心邏輯** 由於型別簽名是實作的第一步，這迫使我在一開始就得先剝離具體問題的附著於算法上邏輯。換句話說，這能使我能更好的去理解這個算法實際的邏輯，而不是這種算法對於某種題型的解法

2. **惰性求值讓某些算法的實作變得極其精簡** 例如 DP 的 `table = listArray bounds [recur table i | i <- range bounds]` 能在創建自己時使用自己靠的正是 Haskell 的惰性求值，在 C++/Python 等非函數式語言裡是不可能這麼寫的，必須得自己排定計算順序、管理快取

3. **型別系統能顯示算法對於資料的限制，反之亦然** 例如 DFS/BFS 裡的 `Ord a`，實際上是因我在內部使用了 `Data.Set` (基於平衡樹的資料結構)，所以才要求資料必須能被排序。實際上 DFS 邏輯本身只需要 `Eq a` (用於判斷是否已經走訪過)，不過如果限制資料只有 `Eq` 的話，時間複雜度會變得更高，所以我認為這是一個必要的取捨（其實可以用雜湊表）


另外，由於我的目的是抽象出算法的邏輯，不是為了效率或是解題，所以優化的部分基本等於沒有。一些像滾動 DP 的優化方法也沒有被實作
